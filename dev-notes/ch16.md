# CH16 开发记录

## 范围与保护

只在独立 worktree `codex/ch16-rag-ablation`（`origin/main` 的 `dde19f3420b6da00c8e28dd9f503e1de4b6cfde9`）实施。CH11 frozen-v1/regression-v1 题目、金标、manifest、历史报告与其他 worktree 均只读。CH13 LightRAG 处于独立实验分支，不纳入已验证方案。

本章复用 CH11 的 `RetrievalService`、答案 prompt、确定性判分、成本守卫与 Milvus Lite 快照，复用 CH12 的 harness 模式和 `ControlledRagLoop`。CH16 不另造题、不改 CH11/CH12 运行实现。候选集 50，进入回答上下文 top 10，模型 `deepseek-flash` 温度 0。RRF 为 `hybrid`，RRF + 重排为 `hybrid_rerank`。

## 重放命令

先检查每个 split 的逐组预算估算：

```bash
python3 -m scripts.eval_rag_ablation --experiment retrieval --split dev --estimate-only
python3 -m scripts.eval_rag_ablation --experiment rag --split frozen-v1 --estimate-only
```

先完成两个 dev 实验并生成协议锁，再运行 frozen。frozen 前会从相同索引与配置重建协议，hash 不匹配则在执行题目之前停止。

```bash
python3 -m scripts.eval_rag_ablation --experiment retrieval --split dev --out tests/eval/rag_ablation
python3 -m scripts.eval_rag_ablation --experiment rag --split dev --out tests/eval/rag_ablation
python3 -m scripts.eval_rag_ablation --experiment retrieval --split frozen-v1 --out tests/eval/rag_ablation
python3 -m scripts.eval_rag_ablation --experiment rag --split frozen-v1 --out tests/eval/rag_ablation
```

单组离线回放依赖输入缓存；缓存 miss 只记录 `unmeasured`。不要通过改用近似问题缓存、把 R@ 命中当答对，或通过 frozen 结果改阈值来填补缺失。新增付费调用需先按 `budget-estimate.json` 逐组报预算并等统一安排；本次运行没有调用付费 API。

## 结果与限制

- 冻结检索：dense、BM25、RRF、RRF + rerank 四组在 65 道有证据题全部可测；最终答案缓存仅 RRF + rerank 全量命中。其他路由没有严格答案质量结果。
- 冻结 RAG：baseline 90/90 缓存可重放；两个复杂组 67/90 可测，23 题被通用零预算守卫中止，逐题记录没有标出具体未命中的缓存组件。所有可测复杂组首轮均充分，`rag_rounds=0`，GapAnalyzer API 次数为 0；配对组只支持“已测题相同”，不支持“复杂循环有效”的结论。
- 回答严格正确率单列 gate-blocked：CH16 主口径对 64 道预期回答 + 事实金标题纳入所有 3 道 gate-blocked 题；漏缓存与 gate-block 的含义不同，前者未测、后者判错。另保留 CH11 兼容已尝试题数，便于与旧报告校验。
- claim 级无证据断言沿用 CH11 的全体非闸拦作答口径；引用支持题率限定到目标回答金标题。延迟是本地重放 wall-clock，不等于真实 LLM 服务耗时。

详情、逐题得失、失败标签、分母、预算和默认路由建议见 [`docs/eval/ch16-rag-ablation-report.md`](../docs/eval/ch16-rag-ablation-report.md) 与 `tests/eval/rag_ablation/runs/`。
