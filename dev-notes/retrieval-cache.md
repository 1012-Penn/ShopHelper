# 检索静态模型缓存

观察到的问题：重复 FAQ 查询仍会重复调用嵌入和重排，单次检索约 0.74 秒，而本地检索
只需几十毫秒。旧的 `scripts/eval_cache.py` 只覆盖评测脚本，不进入应用服务。

采取的动作：在应用侧增加 `CachedEmbedder` / `CachedReranker`，只缓存精确静态输入；
同时加入模型、语料和配置版本键、LRU/TTL 容量限制、并发单飞、失败不缓存和可观测计数。
证据闸和业务动态状态不缓存。

同题实测：私有 130 chunk 索引、真实 BGE 嵌入/重排，每类 8 轮。重复查询 P50
739.8→35.8 ms、P95 2083.8→49.3 ms；热命中 HTTP 16→0。非重复问题集
P50 741.2→27.8 ms。同一缓存实例首次响应与重放逐题一致；语料价格从 299 改到 329 后，
v2 首请求双 miss、次请求双 hit，并返回更新后的证据。

边界：这是检索静态模型阶段，不含查询改写、回答生成、证据裁判和进程冷启动。小样本、
私有本地索引，不是生产流量基准；不能把免费模型的价格写成节省金额。
