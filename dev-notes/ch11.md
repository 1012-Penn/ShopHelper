### 候选方案与推荐

1. **语料来源**：手写小语料 / 结构化事实库+受控渲染文档 / 公开 FAQ。推荐“事实库+受控渲染”，可审计、能构造版本冲突与跨文档证据，LLM 只辅助措辞。
2. **评测框架**：扩展现有 Python 脚本 / 引入 Ragas 等 / 全新自建。推荐扩展现有脚本，复用严格 evidence 口径与缓存，避免新依赖和口径漂移。
3. **标注方式**：单人+LLM 预审+用户终审 / 双人独立标注 / 纯 LLM。推荐第一种，并报告一致率与局限；冻结集 100% 用户复核。
4. **冻结治理**：标签进 git 靠流程 / blind 子集 / 第三方留出。推荐标签进 git + 可选 blind 子集；改题必须升版本并全方法重跑。
5. **Milvus Lite 隔离**：停服务+flock / 停写后复制快照 / 迁 server 版。默认采用“停写/关闭持有文件进程后复制、重开快照并校验哈希与 MySQL/Milvus 计数”；不在线直接复制，在线快照与 server 版留待讨论。
