## Design decisions

- Read and implemented the CH15 section of `docs/superpowers/specs/2026-10-25-ch15-ch17-interview-evidence-roadmap.md`.
- Froze 72 simulated cases before scoring: 14 policy QA, 12 order lookup, 18 refund guidance, 12 multi-turn revisions, 10 refusal/handoff and 6 fault cases. Gold stores final outcome, required/prohibited content, per-turn expected action sequence and arguments, allowed tools, forbidden actions, ticket-count checks and required audit statuses.
- Uses the production `build_graph`, ReAct Agent node, built-in registry, `ToolEngine`, ORM stores and `/api/tickets/confirm` route. A deterministic scripted actor replaces provider models; an offline retrieval fixture replaces live retrieval. Each scenario-arm has a new SQLite in-memory database.
- Paired set is 30 cases / 42 user turns per arm. The original offline harness used the production default graph route in both arms and injected each arm's prewritten intent/actor. Its paired numbers are scripted contract results, not a pure route ablation; the offline report now states this explicitly. The real-model runner adds an opt-in `refund_flow_mode` route switch, preserving `fixed` as the production default and directing refund/aftersales intents to the existing Agent only in the autonomous arm.
- `fetch_order` and `policy_retrieve` are graph nodes, not `ToolEngine` calls. Their `tool_status` events are included in action sequence accuracy; internal `expand` is excluded. Fixed-arm parameter accuracy applies only to actual Agent tool calls and may be `N/A`.
- There is no refund execution tool. `refund_form` is a guidance action. The only registered write tool is `create_ticket`, and it remains confirmation-gated. Fault confirmation writes use only isolated SQLite.

## Offline results

The complete run executed 72 fixed simulated cases and 102 arm-runs. The model substitute is deterministic and scripted; it made no provider call, MCP request, live business-data request or real write.

| Metric | Fixed flow | Constrained Agent |
|---|---:|---:|
| Scripted scenario contract pass | 29/30 (96.7%) | 62/72 (86.1%) |
| Tool selection | 30/30 (100.0%) | 69/72 (95.8%) |
| Parameter accuracy | 3/3 (100.0%) | 81/85 (95.3%) |
| Unconfirmed write rate | N/A (0/0) | 0/7 (0.0%) |
| Reasonable handoff | 1/1 (100.0%) | 9/9 (100.0%) |
| Refusal/gold alignment | 29/30 (96.7%) | 71/72 (98.6%) |

These are scripted scenario contract pass rates, not Agent task success rates. The paired subset passed 29/30 fixed-arm contracts and 28/30 autonomous-arm actor contracts; difference is -1/30 (-3.3 percentage points) for the scripted run. Both offline arms use the production default router; arm-specific intent labels and scripted actors are injected. The values are not a pure route ablation and do not measure a model independently completing tasks. False handoffs were 0/29 and 3/63 respectively. All denominators are in `docs/eval/ch15-offline-report.md`.

Fault outcomes: same-key duplicate confirmation and a simulated post-commit response loss each created one ticket after confirmation; the replay returned the same ticket with `deduplicated=true`. The unconfirmed write attempt produced a preview/permission-denied audit and no ticket. The slow read produced a timeout audit after the configured read retry and no ticket. Invalid arguments were blocked by the real JSON Schema gate. The unknown `delete_order` proposal was not registered or executed.

## Failure cases and limits

- The fixed refund path fell back on `CH15-REV-006` after the corrected unknown order had no matching policy evidence. The constrained Agent used the stale order id in that same scripted case.
- `CH15-RFD-014` deliberately claims a refund completed although no refund record/tool exists; the task is failed and the prohibited claim is captured.
- The Agent refusal path automatically attaches `transfer_human`. That generated three false handoffs on gold-negative cases, including refusals for out-of-scope policy questions. This is existing graph behavior, observed without changing production code.
- `CH15-POL-013` is an intentional false refusal on a question with ordinary-shipping evidence. Gold requires the supported 8-yuan answer, so the refusal does not count as success.
- The scenario and policy fixture are simulated; fixture retrieval uses explicit deterministic match terms rather than production vectors/reranking. Offline intent labels are injected, so the classifier is not measured there. The real-model runner uses the actual classifier.
- The harness calls the production graph directly with `initial_state`, not the full `/api/chat` SSE endpoint. It does exercise the production ticket confirmation endpoint. API transport behavior outside these tested routes is not covered.
- The refusal/handoff sample is small, so its percentages are descriptive of the fixed case list only. There was no real-customer or ROI measurement.

## Real-model experiment

- The real-model comparison is **not run**: no `OPENAI_API_KEY` is present in this worktree or environment. The paid smoke stopped before creating a ledger or making a provider call; spend remains $0.00.
- The authorized separate ceiling is $17.40: 378 calls / $9.20 fixed and 336 / $8.20 constrained Agent; the fixed-arm smoke counts inside its cap. CH11's ledger and frozen set remain untouched.
- Frozen config: `docs/eval/ch15-model-experiment-config.json`; preflight passed with 30 simulated pairs, 42 turns per arm, and 714 maximum model generations. The separate cap is $17.40: fixed 378 calls / $9.20 and autonomous 336 / $8.20, including the smoke in fixed.
- The executor runs real resolver, intent, Agent and ToolEngine paths with deterministic fixtures. It exposes only read-only order/FAQ tools, projects user text and actual conversation history but not actors/gold into prompts, and persists per-call reservations, usage, prompts, outputs and latency to a CH15-only SQLite ledger. Provider errors stop the run; pending calls block restart.
- Structured-output calls now include their schema in the pre-call size/cost envelope and durable request record. The wrapper requests raw provider output internally to capture token usage, then returns the parsed result to the graph unchanged.
- No model task-success, tool, refusal or handoff rate has been produced. The 30-case paid set has zero expected handoffs and no write tools, so those metrics will be N/A (0/0); the offline suite separately covers refusal/handoff and write safety.
- Run `python3 scripts/ch15_model_experiment.py --preflight` for the free integrity check. After a local `.env` or environment variable supplies `OPENAI_API_KEY`, run `python3 scripts/ch15_model_experiment.py --allow-paid --smoke`, then `python3 scripts/ch15_model_experiment.py --allow-paid`.
