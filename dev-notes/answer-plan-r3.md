# Evidence-Bound Answer Plan R3

## 观察

第二轮应用 dev smoke 已没有结构化协议技术失败，事实和条件层也基本通过，
但知识类严格引用支持仍然弱：3 条 uncertain、2 条 unsupported。问题不是
“回答里有没有 [n]”，而是引用证据是否真的绑定了主体、值、单位、日期和
适用条件。

## 定位

本轮先固定同一问题和同一候选证据，只改变最终作答方式，避免把真实检索或
订单事实修复混入机制收益。实现把生成拆成：

1. 结构化计划：claim、subject、value/unit、日期、必要条件、evidence ID、
   原文 quote/span；
2. 确定性校验：ID、原文 span、主体、数值单位、政策范围、条件遗漏；
3. 最多一次有界修正；
4. 只渲染已核验 claim 的 `[n]` 回答。

校验不能证明语义蕴含，所以锚定不足仍保留 `uncertain`，不会升级为通过。

## dev 调试

第一轮 dev 发现计划臂 `0/8`。逐题检查后确认不是模型效果本身：

- 账本把 `succeeded` 状态排除在 committed 计算外，已改为所有非 pending
  记录按实际费用或预留费用计入；
- 汉字数值“一 年”、自由文本 value 和条件别名被误判；
- 渲染器在句号后再放引用，评分器把引用拆成空句；
- 评分器把“一年”或分号子句与引用断开。

这些都用失败测试复现并修复。第二轮 dev 的原始生成中，部分问题只影响校验
和渲染，因此从已保存计划重算，不额外调用模型。修正后的 dev 为自由文本
`7/8`、计划臂 `8/8`；这是看过 dev 后的调试结果，不是 held-out 证据。

## held-out

新 20 题只运行一次。原始冻结 `score-v1`：

| Arm | Strict | Facts | Conditions | Misrefusal |
|---|---:|---:|---:|---:|
| free text | 16/20 | 18/20 | 19/20 | 0 |
| answer plan | 13/20 | 14/20 | **20/20** | 4 |

事后审计发现 `score-v1` 有三个确定性缺陷：多事实共享实体时被一起算作
已提及、同一谓词只看第一处否定、答案/证据使用不同条件别名时没有连接。
新增 `score-v2` 重评全部已保存答案，明确标记为非独立：

| Arm | Strict | Facts | Conditions | Supported / Unsupported / Uncertain |
|---|---:|---:|---:|---|
| free text | 18/20 | 19/20 | 19/20 | 17 / 0 / 1 |
| answer plan | 16/20 | 16/20 | **20/20** | 14 / 3 / 1 |

配对为计划臂 `2胜 / 4负 / 14平`。即使采用修正后的评分，计划臂仍没有
净收益，因此默认关闭。

## 原因

计划臂保住条件，但校验器对常见措辞过严。四个主要失败是 SH-E120 的
“不支持主动降噪”、SH-W30 的“支持独立通话”、SH-T50 的“半年质保”，
以及 SH-S10 的“IPX7 + 12 小时”多事实 claim。计划引用了正确整段证据，
但结构化字段与原文措辞不能直接对齐，于是安全收口为有限帮助。7 次修正中
只有部分把最终计划恢复到严格成功。

这不是“结构化计划普遍差”的结论。它说明当前确定性 anchor 规则对否定能力、
文本值和多事实合成的覆盖面不足；在没有重构验证规则前，不应把该路径设为
默认。

## 成本与边界

- Held-out：自由文本 20 次调用、5,155 input / 3,132 output tokens、
  `$0.00530490`、P95 `2,274.082 ms`。
- 计划臂：27 次调用（含 7 次修正）、25,219 input / 30,581 output tokens、
  `$0.04426290`、P95 `22,390.696 ms`。
- 全部三轮调试和 held-out 共 85 次真实 provider 调用、`$0.100874172`；
  独立 `$2` 上限内无 pending，技术失败 0。

这是固定候选证据诊断，不含真实检索、工具轨迹或生产全图收益。预算账本按
调用前原子预留、usage 后结算；P95 是真实网络请求的端到端时间，不是缓存
重放速度。

## 可讲的两句

> 实现可注入的 evidence-bound answer plan，验证引用 ID、原文 quote/span、
> 主体、数值单位和政策条件；在固定证据 held-out 上条件遵循达到 20/20，
> 但严格成功 16/20 对自由文本 18/20，因此作为负结果保持默认关闭。

> 建立独立 `$2` SQLite provider 账本和计价快照口径，原子预留并结算 85 次
> 真实调用；完整保留 dev 协议调试、一次性 held-out、逐题结果、token、
> 成本、P95 与评分修正记录，不把 uncertain 或事后复算写成独立提升。
