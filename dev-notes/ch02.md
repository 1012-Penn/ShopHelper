  - `ToolRegistry`(commit a5f03d4):未注册/坏 JSON/坏参数/超时/重试全部收敛为错误字符串回灌;pydantic ValidationError 单独捕获归类为「参数校验失败」。
- **拒绝或纠偏**:无。
- **翻车与返工**:
  1. Docker Hub 拉不动 `mysql:8`(registry 超时)→ 本地已有 `mysql:8.4`,compose 改用之。
  2. `docker exec mysql` 客户端默认 latin1,`LIKE '%退货%'` 计数假阴性显示 0;`--default-character-set=utf8mb4` 后实为 2 命中。数据无问题,教训:容器内验证中文必须显式声明客户端字符集。
  3. **真库 ENUM 双层编码**:uvicorn 起服务后第一条 chat 报 `Data truncated for column 'status'`。根因:MySQL 入口脚本以 latin1 连接执行 init.sql,ENUM 里的中文字面量按 latin1→utf8 双层编码存坏(information_schema 里 COLUMN_TYPE 的 HEX 可实锤)。修复:init.sql 顶部加 `SET NAMES utf8mb4;`,`docker compose down -v` 重建卷重放 DDL。
  4. `BigInteger().with_variant(None, "sqlite")` 产生 NullType 编不出 DDL → 变体改用 `Integer`(SQLite 里 INTEGER PRIMARY KEY 才自增)。
