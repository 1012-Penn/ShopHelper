# End-to-End RAG Quality Baseline R2 Implementation Plan

> **For the implementing agent:** Execute inline because the dispatch author explicitly authorized
> direct implementation without another approval checkpoint. Follow TDD for every executable unit.

**Goal:** Diagnose historical RAG scores and produce a real-model, production-path quality baseline
without leaking expected behavior or gold labels into model input.

**Architecture:** A standalone runner prepares a private snapshot/database/cache copy, builds the
real app, submits user turns over `/api/chat`, instruments exact provider calls and graph/tool I/O,
then applies a frozen deterministic scorer. Historical traces are rescored read-only for diagnosis.

**Tech Stack:** Python 3.10 compatible, FastAPI/httpx ASGI transport, LangGraph, SQLAlchemy/SQLite,
Milvus Lite, pytest.

**Spec:** `docs/superpowers/specs/2026-10-27-e2e-quality-r2-design.md`

## Global Constraints

- Work only in `codex/opt-e2e-quality-r2-20261027`; never touch the root worktree.
- Do not edit `app/main.py`, `app/config.py`, `app/graph/`, `app/answer_verifier.py`,
  `scripts/eval_checks.py`, `scripts/eval_multi_agent.py`, `db/init.sql`, or historical results.
- No expected behavior, gold fact IDs, required conditions, scoring rules, target chunk IDs, or
  reference answer may enter model input.
- Data/scorer/config/cache hashes freeze before held-out execution.
- One complete paid run; only an infrastructure failure may receive a bounded retry.
- Preserve all per-case failures and raw model responses.
- Total provider protection cap is $2.00.

## Review Focus

- A case-level answer string accidentally contains a gold key before graph input.
- Cache keys collide across split, turn, tool schema, or prompt version.
- Concurrent budget reservations over-commit the $2 cap.
- A citation label resolves to the wrong evidence number or tool result.
- A user correction is scored against the superseded entity.
- An app fallback/technical error is reported as model failure.
