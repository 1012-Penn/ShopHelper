# CH15–CH17：面试证据补强路线图

- 日期：2026-10-25
- 状态：经面试目标重新定优先级的实施框架；各章实施前仍需提交具体计划
- 基线：CH12 合入后的 `main`；CH13 LightRAG 暂留实验分支
- 目标：让简历中的 Agent、RAG、上下文工程主张有同口径的对照结果和可讲清的失败案例

## 1. 衡量原则

本项目使用模拟电商事实、政策和工具，不存在真实客服运营数据。可以报告“模拟场景任务完成率”“合理转人工率”“每个成功任务的延迟与 Token/API 成本”；不能把这些写成真实客户满意度、节省人力或业务 ROI。禁止编造“从 X 降到 Y”。报告必须写明场景数、分母、模型、提示词、索引快照、成本、失败样本与重复运行情况。

CH11 的 R@10=59/65 是检索指标；严格回答正确率=11/62、claim 级无证据断言=79/150，说明最终效果仍待改进。CH12 三组质量对照尚未实测，不能预设 Agentic RAG 有收益。CH10 微 F1=0.932 来自以模拟题为主的 163 题留出集。冻结集不得用于调参；新方案先在 dev 集调整，冻结后再评一次。

“Agent 的智能在哪里”的回答应落在可测的决策上：模型负责意图、槽位、证据缺口和工具选择；代码约束高风险写操作与权限。固定退款路径和自主工具调用可做受控对照，但不能让实验组在未确认时实际写入。

## 2. 三章可并行开发

### CH15：端到端任务与工具安全

**问题：** 系统能否完成用户任务，且不跳过订单核对、政策判断和写入确认？

**范围：** 新建独立的模拟场景集，首批约 60–80 个场景，覆盖政策问答、查单、退款引导、多轮改口、应拒答或转人工。每题有预期结果、允许的工具序列、禁止动作和最终数据库断言。对固定退款路径与受限自主工具决策做配对比较；故障注入覆盖工具超时、重复确认、写入成功但响应丢失。复用真实图和工具契约，外部订单数据使用确定性 fixture。

**指标：** 任务完成率=全部必要断言通过的场景/该类场景；工具选择与参数正确率分报；不安全写入率与合理转人工率分报；延迟和成本作为取舍。不能把“拒答”一律记为失败，应按题目金标判定。人工复核一部分开放问答，保存逐题轨迹和失败分类。

**所有权：** `tests/eval/tasks/`、`scripts/eval_agent_tasks.py`、`docs/eval/ch15-*`、`dev-notes/ch15.md`；不改 CH11 冻结题、不改线上默认退款路径。若发现真实缺陷，另列最小修复并回归。

### CH16：RAG 消融与答案可信度

**问题：** 向量、BM25、RRF 和重排各贡献了什么？证据命中为何未转化为正确回答？受控补检索何时值得付出额外成本？

**范围：** 同题同索引快照比较向量、BM25、融合、重排，固定返回上下文上限；再在同一回答层比较最终正确、条件覆盖、引用支持和误拒。CH12 的 baseline、decompose_once、controlled_loop 做单独配对对照；CH13 保持旁路，不作为已验证的线上候选。先检查现有 CH11 harness 能否复用，避免重造评测入口。

**指标：** R@3/R@5、MRR、分桶得失、最终严格正确率、claim 级无证据断言、误拒、P50/P95、调用次数与成本。只有同口径且已实测的结果可以写入简历。未达到收益阈值则保留简单默认路由，并解释失败样本。

**所有权：** `scripts/eval_rag_ablation.py`、`tests/eval/rag_ablation/`、`docs/eval/ch16-*`、`dev-notes/ch16.md`；不改 CH11 金标、快照和历史报告。需要付费调用前先提交逐组估算和全局预算守卫；同一台账的付费实验串行。

### CH17：上下文策略与质量—成本

**问题：** 三级上下文策略是否比最近 N 条或统一摘要更好？增加摘要成本后，每个成功任务是否仍划算？

**范围：** 在相同模型、提示词、任务和总预算下，对照最近 N 条、统一摘要、现有三级策略。用确定性多轮场景覆盖早期订单号再引用、用户改口、近期信息覆盖远期信息、过期工具结果；分 10/20/40 轮测，不把 23 轮单机测试称作长期记忆或跨进程恢复。

**指标：** 关键信息保持率、最终任务完成率、总输入/输出/摘要 Token、每成功任务成本、延迟。若三级策略没有净收益，应提出简化或只在特定轮数启用的结论。

**所有权：** `scripts/eval_context_ablation.py`、`tests/eval/context/`、`docs/eval/ch17-*`、`dev-notes/ch17.md`；优先参数化注入，不改主会话路由和生产默认策略。

## 3. 并行与验收

三章从同一已更新的 `origin/main` 建独立 worktree。各章先交设计、题集和评分规则，再跑基线与对照；冻结数据与判分标准在看结果前固定。共用的模型费用台账只允许串行付费运行，不能以文件写锁代替调用期间的预算锁。Codex 逐章复核分母、逐题轨迹、重复运行、失败归因和代码 diff；最终综合报告只收录可复现结果。

最后重写一页简历与面试话术。每条采用“问题—设计决策—对照结果—边界”结构，正文仅放最强的两三个数字。另备三段追问故事：固定退款流程与模型自主决策的取舍、RAG 检索命中但回答失真的定位、上下文质量与成本的权衡。没有真实用户数据时，不写满意度、人工节省或生产级可靠性。

## 4. 暂缓的生产化工作

原草案中的持久 checkpoint、跨用户身份体系、Milvus 服务迁移、长期向量记忆、多 Agent 与微调，均不作为本轮面试补强前置任务。已有的终端用户资源授权缺口仍是真问题：公开演示应使用隔离的模拟数据和受控访问；简历不得声称全用户鉴权或生产就绪。若以后接真实用户或业务数据，应先补资源授权。CH13 的版本身份碰撞和候选截断先留在实验分支修复并复验。
