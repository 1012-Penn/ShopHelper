# 第三轮优化简历证据

日期：2026-10-27

证据 commit：`163ad99f85ef63c2680b31c268aab87568656dae`

以下均为模拟电商任务。简历中必须同时保留小样本、held-out 状态和成本代价。

## 最值得使用的三项

### 1. 同尾号订单主体修复

> 将裸数字与完整 `ORD-*` 隔离为来源可追溯的订单命名空间，修复工具与知识库同尾号串单；
> 在 20 道 held-out 中把主体匹配从 5/20 提升到 18/20、实体串用从 7/20 降到 0，
> 同一任务完成口径从 5/20 提升到 17/20，同时保留 legacy 订单兼容。

证据：

- 事实身份 dev `8/8`，baseline `1/8`；
- held-out identity `17/20`，baseline `5/20`；
- identity 对 baseline 为 `14胜/2负/4平`；
- 订单返回稳定 subject、source、version、as-of 和缺失字段。

边界：

- 28 道模拟题，不能写生产准确率；
- held-out 后修复了日期年份误抓，但没有重跑，原失败仍保留。

### 2. Schema 约束的动作完成契约

> 为客服 Agent 增加 schema 驱动的工单动作契约，从真实工具 registry 注入参数与枚举，
> 用结构化 artifact 表达 preview/awaiting/confirmed/cancelled/failed，并限制一次缺口修复；
> 客户端确认与 confirm-key 幂等仍由 ToolEngine 和工单存储执行。

真实 dev 结果：

> 同模型、同工具 8 题配对中，错误额外预览 `1→0`、创建调用尝试 `8→2`；
> 任务成功保持 `5/8` 对 `5/8`，成本由 `$0.0131205` 降至 `$0.0115809`。

边界：

- 这是动作更少，不是整体任务成功率提升；
- held-out 受评测上限污染，不能写成 held-out 提升；
- 最终真实组合 smoke 的 preview 题失败，confirmed 路径只有集成测试与 source dev 证据。

### 3. 负结果驱动的答案计划取舍

> 实现 evidence-bound answer plan，对 evidence ID、原文 quote/span、主体、数值单位和政策条件
> 做确定性校验，并限制一次修正；固定证据 held-out 中条件保留达到 20/20，
> 但严格成功为 16/20，对自由文本 18/20，因此保持默认关闭。

证据：

- 原评 answer plan `13/20`、自由文本 `16/20`；
- 事后全组审计复算 `16/20` 对 `18/20`，明确不是独立验证；
- 计划臂 27 次调用、`$0.04426290`、P95 `22.4 s`；
- 自由文本 20 次调用、`$0.00530490`、P95 `2.27 s`。

这条适合讲“为什么没有硬上结构化答案”，不适合包装成质量提升。

## 三个面试故事

### 故事一：同尾号不是同一订单

观察到 `1001` 与 `ORD-1001` 被隐含当作同一主体，但金额、状态和商品来源完全不同。
定位发现工具目录与 corpus factbook 缺少命名空间。修复为两个稳定主体和显式来源适配器，
只有确定冲突才过滤证据，泛化政策不误删。held-out 主体匹配提升到 18/20、实体串用归零，
但 scope 没有增加任务成功，因此只保留为可解释的可选能力。

### 故事二：文本说“已预览”不是动作完成

多 Agent 轨迹出现过只有自然语言“预览已生成”、却没有 `create_ticket` artifact 的假成功。
修复从 registry Schema 读取参数枚举，模型文本不再能确认或生成 confirm key；真实写入仍由
ToolEngine 和客户端确认完成。dev 中额外动作和创建尝试下降，但任务完成没有净提升，
所以默认关闭。集成时还补了取消后旧 key 不能重放、确认字段不能篡改的回归。

### 故事三：引用存在不等于语义支持

第二轮的问题不是答案没有 `[n]`，而是引用可能与 claim 主体、数字或条件不匹配。
第三轮把作答拆成结构化 claim、原文 span 和确定性验证，uncertain 从不计为正确。
held-out 原评和事后全组审计都显示计划臂严格成功低于自由文本，主要失败是把否定能力、
文本值和多事实映射到 quote 时过严。最终保留模块和完整负结果，默认关闭。

## 不推荐表述

- “订单准确率从 25% 提升到 85%”：只有 20 道模拟 held-out，不能外推生产。
- “动作契约提高任务成功率”：dev 是 `5/8` 对 `5/8`。
- “结构化答案提升引用正确率”：held-out 两版评分均是负结果。
- “scope 提升回答成功”：scope 只提升 R@K，任务成功与 identity 持平。
- 把三个源实验和 integration smoke 的费用相加后，说成一次运行成本。
- 把 integration smoke 称为新 held-out，或把 `uncertain`、事后重算算成正确答案。
