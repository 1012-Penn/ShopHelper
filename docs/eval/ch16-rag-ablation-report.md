# CH16：RAG 消融与答案可信度对照

日期：2026-10-26。分支：`codex/ch16-rag-ablation`。起点：`origin/main`=`dde19f3420b6da00c8e28dd9f503e1de4b6cfde9`。

## 先看结论

- 检索排序上，`RRF+rerank` 在 frozen-v1 的 R@5 为 50/65（76.9%）、MRR@10 为 0.5159，是四组中观察值最高的方案；但相对 dense 的 R@5 配对得失为 6/2，McNemar 精确检验 `p=0.289`，尚不能证明存在稳定的排序优势。
- 旧判分器的严格通过数为 8–12/64，但仍存在下述引用解析、同义表达和金标适用性问题。这些数值仅保留作历史规则诊断，不能作为真实语义正确率；其 Wilson 区间和配对检验同样不能修复计分偏差，不能据此宣布 BM25 或其他方案胜出。
- 四个检索组的答案层不是纯消融对照：只有 `RRF+rerank` 调用了语义证据判断器，另外三组使用各自的默认分数闸。因此本报告把 R@3/R@5/MRR 视为可比较的检索指标，把严格正确率、条件覆盖、引用支持等称为“策略默认端到端结果”，不把它们解释成 rerank 的单独因果效果。
- CH12 的两种复杂模式在旧评分下相对 `baseline` 均为 0 增、0 失、64 平，R@5 各少覆盖一题。该结果限于当前配置与评分，不证明 Agentic RAG 普遍无效；目前保留 `hybrid_rerank` + `baseline`，等待可靠的语义评分与收益证据后再决定切换。
- 最终答案质量仍需验证。报告中的 8/64 和 85/148 分别是旧规则通过数与规则未支持的断言数，均不直接等于实际答对率或幻觉率；同时确实发现了把同型号另一订单的签收日期套给当前用户的错误，本章不声称已解决回答可信度。
- CH13 LightRAG 仍属于独立实验分支，本章没有把它视为已验证线上方案。

## 合并验收补注：答案判分的已知局限

2026-10-26 Codex 独立复核确认：本轮 `ch16-rescore-1` 只修正了行为分类，尚未修正以下问题。下文所有严格回答、引用支持、条件覆盖及无支持断言数字，均为这套既有规则的诊断值。

- `parse_citations` 按句末标点切分，会把“续航 14 天。[1][2]”的引用与正文分离。仅在内存把引用移到句号前、完全不改模型回答内容，默认组严格通过数即可由 8/64 变为 20/64。这只是格式敏感性探针，不是修正后正式成绩。
- 字面规则不能可靠识别“可取消”与“可以取消”、“一年”与“12 个月”；字符 4-gram 重叠也不等于证据的语义支持。
- 部分金标混淆了背景事实与答案必需事实，例如 `FRZ-MULTI-10` 只问加急费，却同时要求回答商品原价 109 元；`FRZ-MULTI-04` 的具体订单已处于验货阶段，金标仍要求下一步 7 天内寄回，需逐题复核。
- 受控循环 67/90 题在首轮停止；余下 23 题只有 3 题属于有事实金标的回答题，其他为澄清或应拒答题。循环补检索未覆盖大多数最终回答错误，不能据旧规则下的零增益推断复杂方案没有价值。

原题、金标、原始回答和机器聚合保留不改。后续应版本化修正判分与复核金标，再重评这些既有回答；修复计分不需要重新付费生成答案。本次可验收的是检索消融、真实模型实验运行与审计能力，简历仅采用可信的检索数字与工程产物。

## 审计与离线修正

初次聚合后发现确定性行为分类把两类文本判错：自然拒答如“现有证据未提供…无法给出…请转人工”被当成正常作答；带 `【无法回答】` 前缀但实际在追问槽位的文本被当成拒答。这会抬高无证据断言和误拒。

修正只重新判分已保存的模型回答，没有再次请求模型：

- 原始回答、token、费用和延迟保持不变。
- 重算行为预测、引用支持、claim 级无证据断言和失败标签。
- 四份 aggregate 都记录了 `posthoc_rescore.scoring_version=ch16-rescore-1`、`model_calls=0`、`paid_calls=0`。
- 可通过 `python3 -m scripts.eval_rag_ablation ... --rescore-only` 复算；详细命令见 [`dev-notes/ch16.md`](../../dev-notes/ch16.md)。

这次修正改变了部分拒答相关数字，但没有改变任何严格答对数或检索命中数。

CH16 复用 CH11 frozen-v1 的 canonical 问题、金标、判分器、答案 prompt 与 Milvus Lite 快照；复用 CH12 的 `baseline`、`decompose_once`、`controlled_loop` 模式。检索消融比较 vector/dense、BM25、RRF 融合和 RRF+rerank。四组使用同一查询改写、同一语料与索引快照、候选上限 50、答案上下文 top 10、`deepseek-flash` 温度 0。CH12 三组固定 `hybrid_rerank`。

Milvus Lite build 为 `ebfd49478b37ef387c8b124319a450ed73a86ae2a4b9f4fc28d6a52b2ccaa0ba`，快照树 SHA-256 为 `b6b1fa237d03d2c0f8ddcfe8e003f13c4cb584f0764ac04c2d57ae834bbdca73`。dev 数据集 60 题，SHA-256 `a67210c9a2d56ce690eb35fc957f9b75fefb4da365e252f25532196bab5680f7`；frozen-v1 90 题，SHA-256 `f518fe1bd1d7c3c3cd95896a55a06f8160c3f5c82529c1639c8f6e6437fdabf7`。四份 dev/frozen 聚合均保留完整逐题轨迹。

指标定义：

- R@3/R@5 统计 top-k 覆盖全部 required-evidence 组的题：每组命中其任一候选 chunk，组间为 AND；分母只含有检索证据金标的题（dev 43、frozen 65）。MRR@10 同样使用首次覆盖全部组的名次倒数，未覆盖记 0，属于本项目的完整证据覆盖口径。
- 严格正确按预期回答且带事实金标的题计分（dev 42、frozen 64）；事实错、漏条件、禁用断言、引用不支持、误拒或 gate 拦截均为错。
- 条件覆盖为条件题上的逐题覆盖均值（dev 24、frozen 36）。
- 引用支持、无证据断言、误拒的分母都在表中单列。检索命中率没有被当作答对率。
- 二元比例给出 Wilson 95% 区间；配对的 R@k/严格正确使用精确 McNemar 检验，MRR 的逐题方向变化使用精确符号检验。多个指标和组别同时比较，p 值只用于提示不确定性，未做多重检验校正。

冻结协议的机器指纹为 `9998bddfc9a9d3935a248a4bb388a04d30960c4cf0af8a65b14ecbe7bec16d2f`。逐组内容哈希和 dev lock 均在工作树仍为 dirty 的状态下生成，因此可复现依据是契约中的代码与数据哈希，不能仅凭 `locked_at_commit` 声称对应一个干净提交。

## 可比性边界

`answer_comparability` 在机器聚合中记录：vector、BM25、RRF 的 `gate.evidence_entailment` 均为 0 题，`RRF+rerank` 为 90 题。也就是说：

- R@3/R@5/MRR 比较的是四种检索排序，口径一致。
- 答案表比较的是四套“检索 + 默认闸门 + 回答”的端到端表现。
- 答案差异同时包含排序、语义闸门和误拒策略差异，不能归因给 rerank。

如果要比较“同样答案闸门下的纯检索效果”，还需一个 gate-matched 实验，并先修正答案判分。该实验尚未执行；既有逐组估算为 `$0.18`、合计 `$0.72`，只是规划值，不能作为已经执行的实验结果。

## 失败归因

冻结 baseline 的确定性失败标签可以重叠：漏条件 16 题、事实错误 17 题、引用不支持 44 题、澄清遗漏槽位 4 题、澄清追问过多 7 题、误拒 7 题。claim 级无证据断言为 85/148，来自 45 道有无证据断言的题。逐题 ID 保存在 aggregate 与 traces。

复算后，frozen 四组的 expected-refuse 轨迹均已识别为拒答；dev 的 BM25 与 RRF 仍有少量不同措辞没有触发现有短句规则。确定性规则只能覆盖可枚举的格式，不能代替人工语义复核，因此报告保留残余归因风险。

## 建议与可诚实使用的数字

可以诚实写成简历或面试材料的数字包括：

- “在 90 条 frozen-v1 题上做了 vector、BM25、RRF、RRF+rerank 同快照检索消融；RRF+rerank 的 R@5 为 50/65（76.9%），MRR@10 为 0.5159。”
- “完成单轮、一次拆解与受控多轮 RAG 的真实模型对照，记录缺口分析、补检索与预算停止原因；识别答案评分和触发覆盖局限，保留默认策略并提出后续验证条件。”
- “构建了逐题轨迹、配对得失、费用对账和离线可复算契约；审计复算无新增付费调用。”

不应声称“RRF+rerank 显著优于其他策略”“BM25 已证明答案更准”“多轮 RAG 提升了多跳准确率”或“预算上限已在运行时强制执行”。
