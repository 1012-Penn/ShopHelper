# CH16：RAG 消融与答案可信度对照

日期：2026-10-26。分支：`codex/ch16-rag-ablation`。起点：`origin/main`=`dde19f3420b6da00c8e28dd9f503e1de4b6cfde9`。

## 实验契约

CH16 复用 CH11 frozen-v1 的 canonical 问题、金标、判分器、答案 prompt 与 Milvus Lite 快照；复用 CH12 的 `baseline`、`decompose_once`、`controlled_loop` 模式。检索消融比较 vector/dense、BM25、RRF 融合和 RRF+rerank。所有路由使用同一查询改写、同一语料与索引快照、相同候选上限 50、答案上下文 top 10、`deepseek-flash` 温度 0。CH12 三组固定 `hybrid_rerank` 检索。

Milvus Lite build 为 `ebfd49478b37ef387c8b124319a450ed73a86ae2a4b9f4fc28d6a52b2ccaa0ba`，快照树 SHA-256 为 `b6b1fa237d03d2c0f8ddcfe8e003f13c4cb584f0764ac04c2d57ae834bbdca73`。dev 数据集 60 题，SHA-256 `a67210c9a2d56ce690eb35fc957f9b75fefb4da365e252f25532196bab5680f7`；frozen-v1 90 题，SHA-256 `f518fe1bd1d7c3c3cd95896a55a06f8160c3f5c82529c1639c8f6e6437fdabf7`。四份 dev/frozen 聚合均为 100% 题目轨迹测量，无未测轨迹。协议锁 SHA-256 均为 `9998bddfc9a9d3935a248a4bb388a04d30960c4cf0af8a65b14ecbe7bec16d2f`；frozen 运行前逐组验证 dev 锁，冻结结果没有用于调阈值。

指标定义：R@3/R@5 统计 top-k 至少命中一个 required-evidence 金标的题；分母只含有检索证据金标的题（dev 43、frozen 65）。MRR 为 MRR@10。另将“全部必需证据组召回”保存在 aggregate，但不与命中任一证据的 R@k 混称。答案严格正确率另按预期回答且带事实金标的题计分（dev 42、frozen 64）；可答但被 gate 拦截的题按错计。条件覆盖为 24/36 道条件题上的逐题覆盖均值；引用支持为严格答案 eligible 题中引用受证据支持的题数；无证据断言按所有非 gate-blocked 回答的 claim 级微平均；误拒分母是需要回答的题（dev 49、frozen 70）。检索命中率不作为答对率。

API 调用成本按 [DeepSeek 定价页](https://api-docs.deepseek.com/quick_start/pricing/) 与 [SiliconFlow 定价页](https://siliconflow.cn/pricing) 在 2026-10-26 保存的价格快照计算，明细见 [`pricing-snapshot-2026-10-26.yaml`](../../tests/eval/rag_ablation/pricing-snapshot-2026-10-26.yaml)。`BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3` 使用当日 SiliconFlow 标准端点免费价格；DeepSeek 使用当日 `deepseek-flash` 解析模型的峰时缓存未命中价。费用使用提供方返回的实际 token usage 乘以快照单价计算；这不是账户发票或扣款记录。每次调用只尝试一次、不隐式重试；精确请求结果日志用于断点安全与避免相同请求重复计费。

以 dense 为配对基线，RRF+重排的 R@3 得/失/平为 6/2/57，R@5 为 6/2/57，MRR +0.0197；与 RRF 直接配对时，R@3 为 4/4/57（净 0）、R@5 为 6/3/56（净 +3），MRR +0.0509。按桶看，RRF+重排相对 dense 的 multi-hop R@5 +6 题（3→9），multi-constraint R@3 +2；policy-conflict R@3/R@5 分别 −1/−2（3→2、6→4）。重排没有消除冲突题弱点。

严格答案配对也显示检索命中与正确回答并非同一指标。相对 dense，BM25 的严格答案 9 增、5 失、50 平（净 +4）；RRF 为 6 增、6 失、52 平；RRF+重排为 6 增、6 失、52 平。frozen-v1 中 BM25 严格正确率最高（12/64），而 RRF+重排的 R@5 与 MRR 最高；这个 90 题结果存在清晰取舍，不能据此宣布单一策略全面胜出。

端到端延迟按 nearest-rank 算法对每题 wall-clock 汇总；在线 API P50/P95 是费用账本中单次实际请求耗时。端到端列同时包含精确缓存、本地检索与在线调用，不应当解释为纯线上延迟。受控循环 90 题中有 86 题走缓存/本地路径，4 题走在线 API；分源延迟保存在 aggregate。

严格答案配对：`decompose_once` 对 baseline 为 0 增、0 失、64 平；`controlled_loop` 同样为 0/0/64。逐桶观察：

- **multi-hop（16题）**：两复杂模式严格答案均 0 增、0 失、16 平；R@3 全平。baseline R@5 为 9/16，两个复杂模式为 8/16；唯一 R@5/MRR 损失题为 `FRZ-MULTI-01`，没有相应收益题。
- **policy-conflict（8题）**：严格答案有 7 道可配对题，两个复杂模式均 0 增、0 失、7 平；R@3、R@5、MRR 均 8/8 题持平。三组绝对 R@3 均 2/8、R@5 均 4/8。

实际调用和费用还需区分“本次边际支出”与“每组独立冷启动”：CH12 组间启用精确请求响应日志以避免对相同提示重复计费。`baseline` 完整缓存重放；decompose 组完成 140 个外部 API 请求，其中 23 个 GapAnalyzer、40 个证据判断、38 个嵌入、38 个重排和 1 个答案请求；controlled 组完成 21 个外部请求，其中 9 个证据判断、6 个嵌入、6 个重排。Controlled 的 23 次 GapAnalyzer 逻辑请求命中 decompose 先前写入的精确响应缓存，因此 `$0.008586` 是该共享缓存顺序下的实际边际费用，不是独立冷启动估价。预先登记的冷启动估算为 baseline `$0`、decompose `$0.04–0.08`、controlled `$0.07–0.15`。这不会改变同题答案配对，但意味着两种复杂模式的在线延迟/单独生产成本应以请求日志和冷启动估算分开阅读。

## 费用对账、失败归因与结论

执行前的组级预算范围与执行后实际费用如下。范围依据当时 CH11/CH12 实测和定价快照，不是实付；“建议上限”来自各组 `budget-estimate.json`。本次在线请求是在任务内已获逐组预算授权后执行的；未来新增付费调用仍需先报逐组预算并等统一安排。

| split / experiment / group | 执行前估算 USD | 建议组上限 | 本次按实际用量估算 USD |
|---|---:|---:|---:|
| dev retrieval：vector、BM25、RRF、RRF+rerank（每组） | $0.0476–0.1019 | $0.12 | $0.040404 / $0.046693 / $0.046454 / $0.096284 |
| dev RAG：baseline | $0 | $0 | $0 |
| dev RAG：decompose_once | $0.0267–0.0533 | $0.06 | $0.054139* |
| dev RAG：controlled_loop | $0.0467–0.1000 | $0.11 | $0 |
| frozen retrieval：vector、BM25、RRF、RRF+rerank（每组） | $0.0713–0.1529 | $0.18 | $0.067739 / $0.066400 / $0.070549 / $0.110736 |
| frozen RAG：baseline | $0 | $0 | $0 |
| frozen RAG：decompose_once | $0.04–0.08 | $0.09 | $0.078755 |
| frozen RAG：controlled_loop | $0.07–0.15 | $0.17 | $0.008586** |

\* Dev decompose 的 60 题最终轨迹记有 90 次 API / 42 次付费请求、`$0.039272`；累计账本另有 8 次带组标签的早期尝试，故组总支出为 `$0.054139`。另有 15 次丢失上下文的尝试，`$0.019099008`，只计入总账、不分配给组。

\*\* Controlled 的精确调用由 decompose 组先行写入共享响应日志；此值是本顺序下的边际实付。冷启动独立运行仍应按 `$0.07–0.15` 预算，而不是按 `$0.008586` 预算。

本次总账记录 1,274 次成功 API 尝试、0 次失败、0 次未闭合；按实际 token usage 与保存单价估算的调用成本为 **$0.705838302 USD**。分组明细见 [`attempt-reconciliation.json`](../../tests/eval/rag_ablation/runs/attempt-reconciliation.json) 和四份 aggregate 内嵌的 API attempt ledger。费用只统计实际请求，不把本地缓存响应估成调用成本。Dev 初次尝试的 15 次调用失去 split/group 上下文，估算成本 `$0.019099008`，在对账文件中单列，不分摊给任何策略；按运行时间和调用类型推测属于初始 dev RAG 尝试，但没有足够上下文安全归组。其余 1,259 次均有标签。总额与本地 cost ledger 的 amount 合计相等。

冻结 baseline（即 `hybrid_rerank`）失败归因标签可重叠：漏条件 16 题、事实错误 17 题、引用不支持 44 题、澄清遗漏槽位 4 题、澄清追问过多 7 题、误拒 7 题。claim 级无证据断言为 85/148，来自 45 道有无证据断言的题。标签/逐题 ID 保存在 aggregate 与 traces。

**建议保留当前简单默认路由 `hybrid_rerank` + CH12 `baseline`，暂不启用复杂补检索循环。** 冻结结果显示复杂 RAG 模式没有增加一题严格正确答案，多跳 R@5 还损失 `FRZ-MULTI-01`；两复杂模式条件覆盖略降，引用支持和无证据断言没有改善。RRF+重排提高了 top-5/MRR，但 BM25 严格答案数更高，需用更大且独立复现的答案评估确认取舍后再改路由。现有答案可信度仍不足以声称已解决；CH13 LightRAG 仍在独立实验分支，本章不把它视作经验证线上方案。
