# 查询条件感知的证据面重排

日期：2026-10-27。分支：`codex/retrieval-evidence-coverage`。基线：`main=60f29ce54cd2f169a9619569d9bd453d8887d416`。

## 结论

同一 RRF 候选池和同一个 BGE reranker 调用下，Top-5 完整证据覆盖的瓶颈主要不是候选召回，而是精排结果截断为 10 条后仍按单条相关性排序：

- 旧 frozen-v1 的 15 个 miss 全部能在 50 条融合候选中找到完整证据组，9 个在旧 Top-10 内，6 个只在 Top-11~50。
- 实体/订单片段通常单独得分高；回答所需的包邮门槛、会员规则、退款路径、版本分支或第二个退货条件得分较低，被同主题片段挤出前五。
- 此前按来源限额和简单字符 MMR 没有提高 dev，故本轮没有继续扫这些参数。

本轮保留 dense、BM25、RRF 和 cross-encoder 排序，只改变精排后“从候选里拿哪 10 条”：

1. 一次 rerank 请求返回最多 50 个带分候选，仍然只有一次外部重排调用。
2. 从查询中识别显式实体和证据面：订单/商品 ID、运费/优惠、退款/取消、退货条件、保修/人为损坏、政策版本等。
3. 为每个显式证据面保留匹配度最高的候选，再按原精排顺序排列这些槽位；空余槽位由原 reranker 排名补齐。
4. 最终上下文仍固定为 Top-10，评测仍只统计 Top-5 覆盖全部 `required_evidence` 组。

规则只读取查询和候选文本，不读取金标。没有修改旧题、旧金标或旧报告。

## 对照结果

### Dev：规则开发集

| 方法 | Top-5 完整覆盖 | 配对增/失/平 | 证据组召回@5 | MRR@10 |
|---|---:|---:|---:|---:|
| dense / RRF+rerank 基线 | 26/43 (60.5%) | — | 0.7558 | 0.4339 |
| 证据面重排 | **42/43 (97.7%)** | **+16 / 0 / 27** | **0.9884** | **0.6390** |

McNemar 精确检验 `p=0.000031`。分桶：multi-hop `5/11 -> 11/11`，multi-constraint `4/9 -> 8/9`，entity mismatch `4/6 -> 6/6`，policy conflict `1/5 -> 5/5`，single-hop `12/12 -> 12/12`。

唯一剩余 miss 是 `DEV-CONSTRAINT-05`。题面问“95 折后 98 元还能用满 99 减 10 券吗”，候选 Top-5 已包含正确的券门槛和叠加规则；旧金标第二组却指向“包邮门槛与合并订单”。这不是检索失败，本报告未改金标把它算成提升。

### Frozen-v1：已看题集的回归

| 口径 | 基线 | 证据面重排 | 配对增/失 |
|---|---:|---:|---:|
| 旧记录 frozen-v1 | 50/65 (76.9%) | **65/65 (100%)** | **+15 / 0** |
| 同一次新 API 重放 | 49/65 | **65/65** | +16 / 0 |

对照旧记录时，证据组召回@5 从 `0.8641` 到 `1.0000`，MRR@10 从 `0.5159` 到 `0.6805`。新 API 重放基线少 1 题，是因为 `FRZ-MULTI-06` 的第 5/6 名在两次 reranker 请求间发生约 0.004 分互换；该题在证据面重排中第 2 名命中。provider 输出未承诺逐位稳定，因此这里同时保留两行，不把 API 漂移算成方法收益。

该题集在调规则前已被查看，100% 只能作为回归结果，不能作为独立泛化证据。

### 独立 holdout

规则和代码先提交为 `881fa06`，随后才提交独立题集并只运行一次。题集为 `tests/eval/splits/retrieval-slate-holdout-v1.jsonl`，SHA-256 `630e69734eea4aa59823826c91b4456d331768e6097eb03c1aa9fc00d90f8325`，20 题均含证据金标，组合了未在 dev 调参中使用的订单、商品和条件。

| 方法 | Top-5 完整覆盖 | 配对增/失/平 | 证据组召回@5 | MRR@10 |
|---|---:|---:|---:|---:|
| 同次 rerank 基线 | 13/20 (65.0%) | — | 0.8417 | 0.3501 |
| 证据面重排 | **18/20 (90.0%)** | **+6 / 1 / 13** | **0.9583** | **0.4783** |

McNemar `p=0.125`，样本小，不能宣称稳定显著优于基线。分桶：multi-hop `9/10 -> 9/10`（一增一失），multi-constraint `0/4 -> 3/4`，policy conflict `0/2 -> 2/2`，single-hop 与 entity mismatch 均无退化。

## 失败记录

- `SLATE-H19` 未提升：问题同时要求保修费用、人为损坏定义和“是否质量问题需检测”的判定。现有规则抽取了前两个证据面，第三个 `质量问题认定原则` 排在第 6，只差一位。说明固定槽位规则没有完成通用语义分解。
- `SLATE-H20` 是唯一退化：基线 Top-5 含地区运价表；候选先保留了通用“邮费与运费”片段，地区运价表被挤到第 6。实体+地区+运价的组合优先级仍需单独建模。
- Reranker 本身在一次 frozen 重放中出现第 5/6 名微小换位，说明使用 provider 默认排序时必须保留逐题顺序和复算能力。
- 成功率提高不代表回答正确率提高；本轮未重新生成答案，也未把证据覆盖写成答案准确率。

## 延迟与成本

正式 holdout 的端到端检索（含查询嵌入和一次 50 条 rerank）P50/P95 为 `877.991 / 1021.623 ms`；本地证据面选择 P50/P95 为 `0.232 / 0.319 ms`。frozen 冷启动重排 P50/P95 为 `676.035 / 889.652 ms`，dev/frozen 缓存重放为 20-50 ms。

对 10 个题做了 top-10 与 top-50 的同文档、交错顺序在线探测。top-50 相对 top-10 的配对延迟中位数 `+19.962 ms`、P95 `+276.785 ms`，波动较大；没有增加 rerun 调用，成本仍以一次 rerank 请求计。

本轮每次在线运行设置 USD 2.00 硬上限并使用独立台账；最终评测入口已同时把累计台账上限收紧为 USD 2.00。实际执行 231 次 API 请求（169 次 rerank、62 次 embedding），0 次失败、0 次重试、0 次 rewrite/judge/generation；按保存价格快照均为 `$0`，实际估算花费 **USD 0.00**。这不代表其他部署或供应商将来仍免费，也不是供应商发票。

## 是否启用

当前语料和入口边界下，证据面重排值得作为**显式 opt-in** 启用：

```bash
RETRIEVAL_EVIDENCE_SLATE_ENABLED=true
RETRIEVAL_RERANK_POOL_K=50
```

默认仍为关闭，原因是：

- 独立集虽然净增 5 题，但只有 20 题，且出现 1 个真实退化；
- 规则依赖当前文档的标题语义和实体格式，换语料后可能失效；
- 本轮只验证检索覆盖，没有宣称答案正确率、引用支持或用户满意度提升。

适用边界是稳定的商品/订单/售后知识库，查询显式包含实体、条件或政策版本。开放域语料、标题频繁变化、无法稳定识别证据面时不应直接启用。上线时应监控 Top-1/Top-10 分数、证据闸误拒、最终回答引用和逐主题覆盖，并保留一键关闭。

## 简历候选

> 在 ShopHelper 中将 RRF+Cross-Encoder 的 Top-10 截断改为单次 50 候选上的实体/条件/政策版本证据面选择，使 dev Top-5 完整证据覆盖由 26/43 提升至 42/43，独立 20 题由 13/20 提升至 18/20（6 增 1 失）。

面试口径：覆盖率的分子是全部必需证据组都进入 Top-5，不是任一命中，也不是答案正确率；独立集样本小且未达显著，应主动说明退化题和规则边界。

## Agent 入口与开关边界

- 单 Agent 默认入口是 `POST /api/chat`，由主 LangGraph 处理意图、检索/工具和回答。
- Supervisor 多 Agent 是独立入口 `POST /api/multi-agent/chat`，应用启动时会挂载，但不替换 `/api/chat`；handoff 默认 `raw`，`MULTI_AGENT_HANDOFF_MODE=typed` 才启用类型化投影，`MULTI_AGENT_ACTION_CONTRACTS_ENABLED=false` 时行动契约关闭。
- `POST /api/adaptive-routing/chat` 只有在 `ADAPTIVE_ROUTING_ENABLED=true` 时才挂载，默认关闭，不是默认聊天入口。
- 受控 RAG 由 `RETRIEVAL_ROUTE=decompose_once|controlled_loop` 切到商品咨询的 `agentic_retrieve` 节点；默认 `hybrid_rerank`。`RAG_GAP_TRIGGER_ENABLED` 默认关闭，`MAX_RAG_ROUNDS`、`RAG_TOKEN_BUDGET`、`RAG_TIME_BUDGET_S` 和 `RAG_CALL_TIMEOUT_S` 只约束该受控循环。
