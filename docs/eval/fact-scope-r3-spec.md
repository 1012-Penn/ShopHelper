# 订单事实身份与证据作用域 R3 短规格

日期：2026-10-27

## 目标

消除 `legacy_demo` 演示订单与 `corpus-v1` 订单之间的同尾号串用,并给政策检索提供
可解释、保守的主体/版本/日期过滤。

## 身份规则

- 裸数字 `1001` 永久表示 `legacy_demo:1001`,保留既有三单 fixture;
- 完整 `ORD-1001` 表示 `corpus:ORD-1001`,大小写规范化但不与裸数字合并;
- “尾号/后四位”同时命中两个命名空间时返回歧义,不猜主体;
- `get_order()` 成功结果包含 `subject`, `source`, `version`, `as_of` 与
  `missing_fields`; corpus 视图通过显式 manifest 加载;
- 结构化订单事实只提供订单字段;政策版本推导属于 scope 层,不混入身份层。

## 检索 scope

`EvidenceScope(subject, policy_version, reference_date)` 是可选参数;缺省时旧调用完全不变。
仅以下可证明冲突会剔除:

- 文档显式包含另一个 `ORD-*` 主体;
- 标题显式标注另一个政策版本;
- 标题版本已知且事实库生效区间不覆盖参考日期。

没有主体或版本标记的泛化政策保留并标记 `unknown`。作用域过滤为空时不回退到冲突候选。
`scope_status`、剔除原因、未知 chunk 和匹配 chunk ID 随结果返回。

## 评测

8 dev + 20 held-out,固定题集、评分、提示、模型、证据上限和配置 hash。每臂使用独立
调用记录;总新增费用保护上限 $2,最终剩余账本上限 $1.95,初始 dev 已计 $0.0450606。
